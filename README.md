Задача:

Сервис представляет из себя ML - модель которая производит инференс входящих файлов. Скорость обработки 1 файла - от 1 до 30 сек в зависимости от размера файла.

У сервиса 2 канала интеграции: входная очередь и rest api. 


Требования:
Сервис обязан предоставлять гарантии по скорости ответа:
 - входная очередь - 12 часов, в сутки может поступать около 50к запросов с пиками до 1к запросов в минуту
 - rest api - 1 минута для больших файлов (более 1 МБ) и 5 секунд для малых файлов (до 100 КБ), 
в сутки поступает около 5к запросов, преимущественно в дневное время суток (мск)

Имеющаяся инфраструктура:
- k8s
- rabbitry 3.12.13
- postgresql 17.11

Проблема:
Рост нагрузки через входную очередь может замедлить скорость ответа по rest api, очень важно обеспечить высокую скорость
ответа для rest api

Решение:
Нужно обрабатывать запросы через rest api с высоким приоритетом, тк rabbitry 3 версии еще не поддерживает приоритеты, 
нам нужно создать 2 очереди: с высоким (для rest api) и низким приоритетом(для входной очереди) и самостоятельно вычитывать 
запросы из очереди.
